## 🤖 Machine learning

PhishGuard's ML layer reads **only the URL string**. It needs no network access, so it works offline, cannot be fooled by cloaking, and returns a prediction in milliseconds. Four classic scikit-learn classifiers are trained on the same **44 lexical features**. All four give a probability for every scan, and the best one, **Random Forest**, supplies the phishing probability that makes up 60% of the [risk score](#-risk-scoring).

> [!NOTE]
> Every number in this section comes from [`backend/ml/artifacts/metrics.json`](backend/ml/artifacts/metrics.json): model version **`2026.10.24-1812`**, trained 2026-10-24 18:12 UTC. The full training run took **100.3 s**. The same file feeds the **Model Lab** page (`/model`) and `GET /api/analytics/model`, so the README, the UI and the API always show the same results.

### Datasets

All training data is read from **local snapshots** in `backend/ml/data/raw/` (never from live feeds), so a training run can be repeated exactly.

| 🎣 Phishing | [PhishTank](https://phishtank.org/) verified-online feed (snapshot 2026-10-24) | 16,000 | Recent, human-verified phishing URLs |
| 🎣 Phishing | [Phishing.Database](https://github.com/mitchellkrogza/Phishing.Database) ACTIVE list | 12,000 | Current phishing hosts |
| 🎣 Phishing | [OpenPhish](https://openphish.com/) community feed | 241 | Very fresh phishing URLs |
| ✅ Legitimate | PhiUSIIL legitimate domains, augmented | 40,753 | Broad set of real sites |
| ✅ Legitimate | [Tranco](https://tranco-list.eu/) top-30k domains, augmented | 21,825 | Popular sites |
| ✅ Legitimate | Real human-facing sub-domains from the Tranco list (`docs.`, `shop.`, `login.` ...) | 6,448 | Legitimate sub-domain hosts |
| ✅ Legitimate | Real deep links from the public sitemaps of Tranco top-30k domains | 4,097 | Real article, product and docs URLs |
| | **Total** | **146,364** | **73,241 phishing / 73,123 legitimate** (almost exactly 50/50) |

**Split.** `StratifiedGroupKFold` makes an **80/20 split: 117,092 train / 29,272 test**. The groups are campaign keys (phishing) or domains (legitimate), so no campaign or domain is in both train and test. Five-fold cross-validation inside the training part uses the same grouping.

**Realistic held-out set (`modern_eval`).** There is also a separate set of **4,000 URLs** that is never used for training or model selection inside a variant:

| Part | Size | How it is kept unseen |
|---|---:|---|
| PhishTank URLs | 1,000 | Their whole campaign keys are removed from training |
| Phishing.Database URLs | 1,000 | Their whole campaign keys are removed from training (hosts left bare, as published) |
| Legitimate sitemap deep links from Tranco ranks 30,001-60,000 | 2,000 | Every domain in that rank range is excluded from the legitimate training data (at most 2 URLs per domain) |

### Data cleaning and bias handling

Phishing and legitimate URLs come from very different places (threat feeds against popularity lists), so a naive model learns *how the data was collected* instead of *what phishing looks like*. [`backend/ml/train.py`](backend/ml/train.py) removes these shortcuts:

| Problem | Fix in `train.py` |
|---|---|
| **Duplicate campaigns.** One kit is often deployed on hundreds of URLs of the same domain, and feeds overlap. | Phishing URLs are deduplicated across all sources (scheme ignored) and **capped at 3 URLs per campaign key**. The key is the registered domain, PSL-private-aware, or the tenant host on free-hosting platforms such as `x.vercel.app`. |
| **Legitimate = bare homepages.** Every PhiUSIIL legitimate URL is a bare `https://www.<domain>`, so "has a path" would look like phishing. | Legitimate hosts are augmented: `www.` is toggled, **about 40% get a realistic synthetic deep-link path** (about 15% of those carry a query string), and about 10% of bare domains get a common sub-domain. They are mixed with **real sitemap deep links (max 6 per domain)** and **real sub-domain hosts (45% given a path)**. |
| **Phishing.Database = bare hosts.** The list has hosts only, so "no path" would look like phishing. | Their scheme is filled in at **PhishTank's HTTPS rate (0.93)**, and **41% of the training hosts** (PhishTank's own path rate) borrow the path and query of a random *training* PhishTank URL. Hosts that are a Tranco top-100k site or an official brand domain are dropped as probable feed false positives. |
| **Label noise in the legitimate class.** | A legitimate URL is dropped if its host also appears in any phishing source, sits on a free-hosting platform, or is a URL shortener. |
| **Train/serve skew.** | Every URL is normalised the same way in training and at prediction time: trimmed, lower-cased, default scheme added, trailing slash removed (`normalize_url` in [`features.py`](backend/ml/features.py)). |
| **HTTPS bias** | See [the HTTPS-bias fix](#the-https-bias-fix) below: the scheme is not a model input at all. |

An optional `--balance-strata` mode (equal phishing and legitimate counts per path-depth and query stratum) was also evaluated. It did not improve the realistic set, so it is off by default.

### The 44 lexical features

[`backend/ml/features.py`](backend/ml/features.py) computes 45 features from the URL string. `uses_https` is shown in the report but is **not** a model input, so the model uses **44**. Brand checks work on token and label boundaries with an allowlist of official brand domains, so `purchase.com` does not match "chase" and `googleusercontent.com` is not flagged.

### The four models

All four are built in `make_models()` in [`train.py`](backend/ml/train.py) with `random_state = 42`, trained on the same 44 features, and saved to `backend/ml/artifacts/*.joblib`:

| Model | Exact scikit-learn setup | Notes |
|---|---|---|
| **Logistic Regression** | `make_pipeline(StandardScaler(), LogisticRegression(C=1.0, max_iter=3000))` | Linear baseline, features standardised |
| **Decision Tree** | `DecisionTreeClassifier(max_depth=20, min_samples_leaf=5)` | Single interpretable tree |
| **Random Forest** ⭐ | `RandomForestClassifier(n_estimators=150, min_samples_leaf=2, n_jobs=-1)` | 150 trees; set to single-threaded (`n_jobs = 1`) when served, for low latency on one URL |
| **Support Vector Machine** | `CalibratedClassifierCV(make_pipeline(StandardScaler(), Nystroem(gamma=0.03, n_components=500), LinearSVC(C=1.0, dual=False, max_iter=5000)), method="sigmoid", cv=3)` | RBF kernel approximated with 500 Nyström components; sigmoid (Platt) calibration gives probabilities; fitted on a stratified **40,000-row subsample** to keep training time reasonable |

### The HTTPS-bias fix

"HTTP means phishing" was true years ago. It is not true now: free TLS certificates and free hosting platforms serve HTTPS by default. The training data still carries the old pattern:

| Share of URLs using HTTPS | Value |
|---|---:|
| Phishing URLs in the training data | 62.7% |
| ↳ PhiUSIIL phishing (older academic corpus) | 45.4% |
| ↳ PhishTank / Phishing.Database / OpenPhish | 88.5% / 93.1% / 63.5% |
| Legitimate URLs in the training data | 92.5% |
| **Phishing URLs in the realistic held-out set** | **90.3%** |
| Legitimate URLs in the realistic held-out set | 97.8% |

A model that can see the scheme learns the shortcut "no HTTPS means phishing". That gives every modern HTTPS phishing page a free "looks safe" bonus. So `train.py` trains **two feature variants** of all four models and compares them on the realistic set:

| Model | Test F1 with `uses_https` (45 features) | Test F1 without (44) | Realistic F1 with | Realistic F1 without | HTTPS-phishing recall with | HTTPS-phishing recall without |
|---|---:|---:|---:|---:|---:|---:|
| Logistic Regression | 89.25% | 80.45% | 86.96% | 88.00% | 77.89% | **82.11%** |
| Decision Tree | 91.82% | 83.72% | 85.23% | 83.89% | 82.88% | **83.38%** |
| **Random Forest** | 93.42% | 85.61% | 86.48% | 86.16% | 83.71% | **84.82%** |
| Support Vector Machine | 91.45% | 83.29% | 85.84% | 86.37% | 80.61% | **83.38%** |

- With the scheme, test F1 is about 8 points higher, but almost all of that gain disappears on the realistic set. That shows it was the shortcut, not real skill.
- Without the scheme, **every model catches more HTTPS phishing**, which is the case that matters today.
- Selection rule in `main()`: take the best model of each variant by test F1, and **keep the scheme-free variant unless its realistic F1 is more than 0.5 points lower**. Random Forest without the scheme scores 86.16% against 86.48% with it (0.32 points lower), so the deployed model is the **44-feature, scheme-free** variant (`"feature_variant": "without_scheme"`).
- The scheme is not ignored completely. The live engine still has an `https_scheme` check, but it is only a small heuristic warning (weight 2) instead of a learned shortcut.

### Why Random Forest is the best model

- **Selection rule.** `train.py` picks the model with the highest **test F1**: Random Forest with 85.61%. It also has the highest test accuracy (86.38%), recall (80.98%) and ROC-AUC (0.9449). Its CV F1 of 85.50% ± 0.23 shows the result is stable and not a lucky split.
- **It catches the most phishing where it counts.** On the realistic set it has the highest recall (84.7%), the highest HTTPS-phishing recall (84.8%) and 93.3% recall on unseen PhishTank campaigns.
- **It fits the data.** It works directly on mixed counts, ratios and yes/no flags without scaling, learns interactions such as "long sub-domain on a free-hosting platform", and its feature importances drive the Model Lab charts.
- **The honest trade-off.** Logistic Regression has the fewest false positives on the realistic set (4.1% against 11.9%) and SVM a slightly higher realistic F1 (86.37% against 86.16%). PhishGuard handles Random Forest's false positives in the scoring layer: the ML probability is only **60%** of the risk score, and popular or official domains with no blocklist hit are **capped at 30** (see [Risk scoring](#-risk-scoring)).

### How the explanations work

Every scan returns the probabilities of all four models plus an explanation of the best model's decision (`predict()` in [`backend/ml/predictor.py`](backend/ml/predictor.py)). It is a **perturbation method** (each feature is put back to a typical value and the change is measured), not a black box:

1. Extract the URL's 44 features.
2. The baseline is a "typical legitimate URL": the **median of every feature over the legitimate training rows**, stored in `metrics.json` as `legit_median`.
3. For each feature whose value differs from that baseline, make a copy of the vector with **only that feature reset to the median**. All copies are scored in one batch call, so this is cheap.
4. **Impact = P(phishing) with the real value - P(phishing) with the baseline value.** A positive impact is shown as **risk**, a negative one as **safe**. Changes below 0.0001 are dropped, and the 10 largest by size are returned.

**Example: `https://www.reddit.com/r/netsec`** (Random Forest gives 52.2%; the other models give Logistic Regression 16.0%, Decision Tree 55.6%, SVM 19.0%):

| Feature | Value | Impact on P(phishing) | Direction |
|---|---:|---:|---|
| Number of slashes | 2 | +13.3 pts | 🔴 risk |
| Registered domain name length | 6 | -7.2 pts | 🟢 safe |
| Domain name entropy | 2.25 | -6.8 pts | 🟢 safe |
| Average token length | 3.8 | -2.5 pts | 🟢 safe |
| URL entropy | 3.59 | -1.6 pts | 🟢 safe |
| Path length | 9 | -1.5 pts | 🟢 safe |

The baseline legitimate URL has no path, so the forest finds a deep link a little unusual. This borderline ML result is exactly why PhishGuard never uses the ML probability alone: the live checks and the Tranco-popularity cap bring this scan's final risk to **30 (Legitimate, tier Favorable)**.

The predictor loads the models once, behind a lock. If it finds the artifacts half-replaced during a retrain (feature count in a `.joblib` file not matching `metrics.json`), it tries up to 5 times before giving up.

### Retraining the models

The trained models are committed in `backend/ml/artifacts/`, so retraining is optional:

```bash
cd backend
.venv/bin/python -m ml.collect_legit   # optional, needs internet: real legit deep links from public sitemaps
.venv/bin/python -m ml.train           # about 2 minutes: dataset -> features -> 2 variants x 4 models -> artifacts
```

| Input in `backend/ml/data/raw/` (git-ignored) | Needed |
|---|---|
| `PhiUSIIL_Phishing_URL_Dataset.csv` (UCI #967) | Yes |
| `top-1m.csv`: Tranco list of registered domains | Yes |
| `feeds_snapshot_20261024/` with `phishtank.csv`, `phishing_database.txt`, `openphish.txt` (a copy of `backend/data/feeds/`) | Yes |
| `tranco_sub/top-1m.csv`: Tranco list with sub-domains | Optional |
| `sitemaps/legit_deeplinks*.csv`: output of `ml.collect_legit` | Optional |

- **Outputs:** `ml/data/dataset.csv`, `ml/data/modern_eval.csv`, the four `.joblib` models and `metrics.json`. Every file is replaced atomically, models first and `metrics.json` last, so a running API never loads a mismatched set.
- **Flags:** `--no-save` (train and print the results without replacing the models or `metrics.json`) and `--balance-strata` (the experimental per-stratum balancing described above).
- Restart the API afterwards so it loads the new models. The Model Lab page then shows the new metrics automatically.
